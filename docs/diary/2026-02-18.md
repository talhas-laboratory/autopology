# 2026-02-18

## Context

Reworked product docs in `docs/update_docs/` changed the target implementation from Python/SQLite prototype semantics to a strict Node + Neo4j MCP architecture with progressive disclosure, budget enforcement, and intent-first tooling.

## Symptoms

- Existing prototype had useful indexing and graph traversal, but output contracts and tool semantics diverged from new v1 requirements.
- No mandatory caching tiers or unified progressive schema existed.

## Root Cause

Initial prototype optimized for local installability and speed to first value, while updated product design optimized for agent-oriented query semantics and explicit interaction contracts.

## Fix

Started hard-break rewrite:

- New Node monorepo packages: `core`, `indexer`, `storage-neo4j`, `mcp-server`, `cli`, `runtime-hooks`.
- Added Neo4j schema/bootstrap and GraphRepository.
- Implemented 8 MCP tools and resource URIs.
- Implemented progressive output builder + budget manager.
- Implemented hot/warm/cold cache system with freshness stamping.
- Added baseline TS/JS + Python indexing and data-flow extraction for P0 `follow_data`.
- Added v2-lite runtime ingest command and service.
- Added tests for IDs, security, budget, cache tiers, progressive output contract, and `follow_data` output.

## Follow-ups

- Improve data-flow precision heuristics and confidence calibration.
- Add deeper integration tests against a live Neo4j instance.
- Add richer test binding extraction from real test frameworks.

## Retrieval Hardening (Phase 1)

### Context

Identified context-quality gap: target resolution relied mostly on lexical `CONTAINS` matching and fixed confidence constants, which made tool confidence look stable even when evidence quality varied.

### Changes

- Added a local-first hybrid retrieval scorer (`packages/storage-neo4j/src/retrieval.ts`) that combines:
  - lexical match signals,
  - token-level semantic similarity (deterministic soft match),
  - graph priors (`priority_score`, local degree),
  - calibrated confidence from evidence quality.
- Updated `GraphRepository.findTarget` to:
  - use candidate recall + hybrid rerank,
  - expose per-hit `confidence_components`,
  - provide evidence narrative in `relevance`.
- Updated `GraphRepository.resolveConcept` to reuse hybrid retrieval results rather than separate lexical-only query logic.
- Updated MCP `ToolService` confidence handling for `find_target` and `resolve_concept` to aggregate item-level confidence and surface top evidence in summary findings.
- Added unit tests for retrieval tokenization, ranking behavior, low-evidence confidence caps, and evidence narratives.

### Verification

- `npm test` passes (Neo4j integration suite still env-gated).

## Follow-Data Hardening (Phase 2)

### Context

`follow_data` previously relied on direct symbol-to-field edges only, which underrepresented caller-mediated mutations and produced confidence that did not consistently reflect partial/interprocedural trace quality.

### Changes

- Added interprocedural caller propagation for data flow in `GraphRepository.followData`:
  - expands direct `READS/WRITES/TRANSFORMS` steps through `CALLS*1..2`,
  - marks inferred steps as `trace_kind=interprocedural`, `partial_trace=true`,
  - records `flow_depth` and `via_node` provenance.
- Added deterministic deduplication for direct+inferred steps (confidence-first, lower-depth preference).
- Added interprocedural confidence decay based on hop depth.
- Updated `ToolService.followData` summary to expose:
  - direct vs inferred step counts,
  - operation coverage (`READ/WRITE/TRANSFORM`),
  - existing persistence/instance findings.
- Recalibrated `follow_data` tool-level confidence from evidence mix (direct ratio, partial ratio, operation coverage, per-step confidence) instead of simple mean.
- Added tests validating:
  - direct/inferred summary reporting,
  - confidence down-calibration under mostly inferred partial traces.

### Verification

- `npm run typecheck` passes.
- `npm test` passes (Neo4j integration suite remains env-gated).

## MCP Retrieval + Linkage Hardening

### Context

High-stakes dual-run evaluation showed MCP was valuable for risk context but lagged lexical-first triage on first-pass precision/recall and test discovery.

### Changes

- Upgraded retrieval scoring (`packages/storage-neo4j/src/retrieval.ts`) with intent-aware weighting and stronger path/file lexical signals.
- Added deterministic MCP lookup tools:
  - `find_file_exact(path)`,
  - `find_tests_by_path(path)`.
- Extended `GraphRepository.getTestsForFunction` from single direct-edge lookup to multi-strategy linkage:
  - direct `TESTS` edges,
  - called-name alias matching,
  - call-chain inference from test-like callers.
- Added exact file lookup and file->test lookup repository methods:
  - `findFileExact`,
  - `findTestsByPath`.
- Added short-lived repository memoization for repeated target resolution and find-target calls.
- Added MCP service startup warm-up and in-flight freshness dedupe, while keeping strict freshness correctness for sequential calls.
- Added effectiveness regression gate test (`tests-node/mcp-effectiveness-gate.test.ts`) and wired it into:
  - `npm run test:effectiveness`,
  - `.github/workflows/ci.yml`,
  - `.github/workflows/release.yml`.
- Updated MCP tool surface contract tests for new tool names and count.
- Recorded ADR 0006 for this interface/behavior change.

- `npm test` passes.
