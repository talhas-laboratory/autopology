# 2026-02-21

## Context

Users asked for strict per-repo graph isolation when MCP is activated in different repositories, while keeping OSS local installability and deterministic behavior.

## Symptoms

- Shared Neo4j database state could overlap between repos.
- Graph metadata was global (`graph-meta`) and repo root node ID was global (`repo:root`).
- MCP/graph queries had no active-repo partition guarantees.

## Root Cause

Storage and repository logic modeled graph state as a single global graph per database instead of repo-scoped subgraphs.

## Fix

Implemented repo-scoped isolation in shared Neo4j:

- Added deterministic repo scope utilities in `packages/core/src/scope.ts`.
- Updated schema init to create per-scope graph metadata and scoped repo root node.
- Partitioned warm cache by repo key and migrated uniqueness to `(repo_key, key)`.
- Refactored `GraphRepository` to:
  - require repo scope context,
  - scope internal node IDs,
  - enforce scope filtering in query paths,
  - provide active-repo fail-closed readiness checks.
- Updated runtime ingestion to scope runtime aggregates/windows and graph-meta updates.
- Wired scope through CLI and MCP server startup.
- Added `autopology graph prune --repo <path>`.
- Added MCP config pin mode: `autopology mcp configure ... --pin-repo`.
- Added scope/error/config tests and updated integration test wiring for scoped behavior.

## Follow-ups

- Add dedicated multi-repo integration test that indexes two repos into one live Neo4j DB and asserts zero cross-repo results for each MCP tool.
- Add targeted query performance checks for scope-filtered hot paths on larger datasets.
- Consider optional explicit operator command for legacy unscoped graph cleanup.

## Additional Hardening (Agent Workflow + Retrieval Precision)

### Context

Agent-style MCP smoke checks were working but often required ad-hoc scripts, and generic `find_target` queries could over-rank noisy data-like nodes.

### Fix

- Added first-class CLI workflow smoke:
  - `autopology mcp smoke --repo <path>`
  - Runs `find_target -> trace_impact -> understand_codebase` with deterministic trace-node selection and structured output.
- Wired this workflow into server smoke verification:
  - `scripts/release/verify-server-smoke.sh` now includes an MCP workflow check before stdio startup smoke.
- Added retrieval ranking hardening:
  - Introduced explicit `dataIntent` detection in retrieval scoring.
  - Penalized `DataObject/Field` results for generic queries.
  - Boosted `DataObject/Field` results when query explicitly targets data/field semantics.
  - Added shape-penalty for synthetic/noisy data-node names when query is not data-focused.
- Added regression tests in `tests-node/retrieval-ranking.test.ts`.

### Follow-ups

- Add a Neo4j-backed integration test for `autopology mcp smoke` output schema stability.
